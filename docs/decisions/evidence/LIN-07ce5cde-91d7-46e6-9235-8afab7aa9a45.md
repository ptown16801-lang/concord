## Purpose

This document defines the implementation contract for the **Research Library** as a distinct Concord subsystem with a first-class page/surface, not as a separate project. It is intentionally separate from Global Search, the Institutional Learning Library, the Concord Artifact Archive, the Archivist/public-ledger subsystem, and the Data Atlas.

## Route and page identity

Canonical page name: `Research Library`

Logical clean-path route: `/research-library`

Logical paper detail route: `/research-library/:govId`

Optional logical graph route/state: `/research-library/:govId/graph`

**Current single-file Workbench deployment:** `#/research-library` and `#/research-library/GOV-###`. These hash routes implement the same page-state contract without requiring server-side rewrite support. A future hosted router may expose the clean-path forms without changing canonical identity or module ownership.

Deep links from Global Search, Workbench help, Data Atlas, or Learning Library must resolve into the Research Library page state when the target is a scientific GOV record.

## Canonical identities

### Bibliographic node

`gov_id` is the canonical record identifier.

A GOV record exists independently of whether a PDF is currently attached, missing, mismatched, or quarantined.

### Physical attachment

Google Drive `file_id` identifies a physical PDF attachment. A filename is display metadata only and must never be treated as identity proof.

### Relationship identity

Every graph edge must be keyed by canonical source/target GOV IDs and include its signal/evidence type. A citation edge, semantic-similarity edge, taxonomy edge, reviewed relation, authorship edge, and mathematical-similarity edge are distinct records.

## Core page regions

### 1. Research Library header

Contains:

* page title and research-specific navigation state;
* library-wide search/filter control scoped to Research Library data;
* verification-state filter;
* A–W family filter;
* year/author/journal filters;
* view toggle: list / graph / comparison.

This search is a page-local research filter. Global Search may call into it but does not own it.

### 2. Paper catalog

Each result row/card must expose:

* GOV ID;
* canonical title;
* authors and year;
* A–W family;
* attachment verification state;
* direct-citation count where available;
* semantic-neighbor indicator where available;
* Drive/PDF availability without implying verification.

### 3. Canonical paper detail

The detail view owns the canonical state for one GOV record.

Required sections:

* canonical bibliography metadata;
* project relevance note;
* A–W taxonomy and logical tags;
* attachment state and Drive link;
* identity-audit evidence;
* semantic neighbors;
* direct citations and cited-by links;
* shared references / bibliographic coupling;
* shared authors;
* reviewed contextual relations;
* mathematical relationships when present;
* provenance for every relationship.

### 4. Relationship graph

Graph controls must expose signal layers independently:

* semantic similarity;
* direct citation;
* cited-by;
* bibliographic coupling / shared references;
* taxonomy;
* authorship;
* analyst-reviewed relations;
* mathematical similarity.

Signal layers may be toggled individually. Do not hide them behind a single unexplained combined score.

### 5. Comparison workspace

Allow 2–4 GOV records to be compared without duplicating PDFs.

Comparison dimensions:

* canonical metadata;
* taxonomy;
* project relevance;
* semantic similarity;
* citation relationships;
* shared references;
* mathematical relationships;
* analyst notes/reviewed relations.

## Verification-state model

Allowed attachment states:

* `NO_ATTACHMENT`
* `PASS_SNIPPET_MATCH`
* `PASS_CONFIRMED`
* `UNCERTAIN`
* `MISMATCH_CONFIRMED`

Rules:

* PDF-derived full text, citation parsing, and mathematical extraction require `PASS_CONFIRMED`.
* `PASS_SNIPPET_MATCH` is preliminary evidence only.
* `MISMATCH_CONFIRMED` never mutates the canonical GOV record into the identity of the wrong PDF.
* Corrections are auditable; prior attachment-audit conclusions are retained rather than silently overwritten.

## Data contract

### Contract versioning

The structures below are the **normalized logical contract**. The current static Workbench build uses a schema-versioned v1 deployment profile that flattens some fields for lightweight browsing—for example, author display text and attachment verification/file fields may be serialized directly on the paper record, and graph edges currently use compact `source`/`target`/`type`/`evidence` keys. This is a known representation difference, not a second identity model. Normalization work must preserve `gov_id`, attachment provenance, evidence provenance, and fail-closed validation.

This normalization gap is tracked separately from the already-completed v1 publish validator so a future representation migration cannot be mistaken for a failure of the current validated build.

## Static artifact contract

The browsing site should consume generated static artifacts rather than requiring a permanent backend service.

Initial artifact set:

* `research-papers.json`
* `research-edges.json`
* `research-neighbors.json`
* `research-citation-graph.json`
* `research-math-graph.json` when available
* `research-attachment-audit.json`
* optional vector/index artifacts used only by the build/indexing step

Google Drive remains the canonical PDF store.

## Integration boundaries

### Global Search

May index Research Library canonical metadata and deep-link to the Research Library paper state (currently `#/research-library/GOV-###` in the single-file Workbench; logically `/research-library/:govId`). It must not maintain an independent mutable copy of canonical paper identity or relationship state.

### Institutional Learning Library

May cite/cross-link GOV records. Its generated guides retain their own page and identity system.

### Data Atlas

May visualize the Research Library graph or filtered projections. It is a consumer, not the canonical owner of Research Library nodes/edges.

### Concord Artifact Archive

Stores project artifacts/change outputs, not the scientific bibliography itself.

### Archivist/public-ledger system

Has no ownership relationship to the scientific Research Library. Research-library indexing/audit logs are not governance public-ledger records.

## Loading and failure behavior

* Missing graph artifact: catalog/detail still loads; affected layer is marked unavailable.
* Missing PDF: canonical GOV record remains available.
* Mismatched PDF: detail shows quarantine state and prevents PDF-derived enrichment.
* Failed model result: prior verified graph artifacts remain intact; never replace them with partial output silently.
* Duplicate GOV ID in generated output: fail build closed.
* Edge referencing unknown GOV ID: fail validation and exclude publication of the new graph build.

## Build validation

A Research Library graph build is publishable only if:

1. all GOV IDs are unique;
2. all edge endpoints resolve to canonical GOV records;
3. no PDF-derived edge originates from a non-PASS_CONFIRMED attachment;
4. canonical metadata remains independent of Drive filenames;
5. artifact schema versions are recorded;
6. failed/partial builds do not replace the last valid static artifact set.
