## Required page identity

The Concord application must expose a first-class navigation destination named **Research Library** with its own route/page state.

The current single-file Workbench implements this as `#/research-library` and `#/research-library/GOV-###`; those hash states are the deployment form of the logical `/research-library` route contract.

The Research Library page owns:

* canonical GOV bibliographic records;
* Google Drive scientific-PDF attachments;
* attachment identity verification/quarantine state;
* A–W scientific concept-family classification;
* semantic paper-neighbor relationships;
* direct citations and cited-by links;
* shared-reference/bibliographic-coupling relationships;
* reviewed contextual relationships;
* mathematical-expression relationships when available;
* historical-research vs modern-comparison views.

## Canonical identities

* **GOV ID** = canonical bibliographic identity.
* **Google Drive file ID** = physical attachment identity.
* PDF filename = display metadata only; never sufficient identity evidence.

One scientific paper should have one canonical GOV node and one physical PDF attachment where available, with multiple logical graph relationships rather than duplicated PDF copies.

## Module boundaries

### Global Search

Global Search may index Research Library metadata/text and deep-link to Research Library records. It does not own Research Library state and must not replace the Research Library page with a generic search-results surface.

### Institutional Learning Library

The generated guides/learning corpus is a separate content surface. It may cite or link to Research Library papers but does not share canonical identity, attachment-verification state, or research-graph ownership.

### Concord Artifact Archive

The artifact archive stores Concord-produced project artifacts. It is not the scientific research library.

### Archivist / authoritative governance records

The institutional Archivist, public ledger, secret failure ledger, protected investigatory archives, and frozen governance evidence are outside Research Library authority. The Research Library organizer must never manage those stores.

### Data Atlas / graph visualizations

The Data Atlas may visualize Research Library graph data, but visualization does not become the canonical graph authority.

## Storage and hosting

Google Drive remains canonical PDF storage. Heavy indexing, scientific embedding, citation parsing, and math extraction should run as batch/offline jobs. The normal Concord web page consumes generated static indexes/graphs and should not require a permanent vector database, model server, or secondary research datastore.

## Non-conflation acceptance test

A build does not pass if any of the following are true:

1. Research Library has no dedicated navigation/page destination.
2. Research Library data is accessible only through Global Search or a floating generic reader.
3. Institutional learning guides and scientific GOV records share the same canonical entity type without an explicit boundary.
4. Artifact Archive or Archivist/governance records are stored or managed as ordinary Research Library papers.
5. Graph visualization becomes the only persisted representation of research relationships.
6. PDF filenames are treated as canonical paper identity.

This document is the subsystem boundary contract for the Research Library within Concord. It does not establish another actual project or change the existing hold.
