## F1 — high: source repair bypasses mandatory independent review

Canonical implementation owner: <issue id="2f07cdad-35d9-4aa3-a2d7-94164f116692" href="https://linear.app/jons-garage/issue/JON-85/implement-frozen-bootstrap-impeachment-specification-codex-handoff">JON-85</issue>, existing PR <pull-request id="4c6c0e58-58e9-4eaf-878b-9df4c95b135f" href="https://linear.app/jons-garage/review/jon-85-recover-and-correct-frozen-bootstrap-impeachment-implementation-7857010e5e77">ptown16801-lang/concord#36</pull-request> only. [Reproduction and producer handoff](<https://linear.app/jons-garage/issue/JON-85#comment-b985004b-c440-40d3-842e-c46d63cc7fd5>). [Linear independently confirmed the contract/source defect](<https://linear.app/jons-garage/issue/JON-86#comment-875a506b-33fc-4602-b1b7-b944baf1f5ed>).

An authenticated clerk has OPEN, COMMIT_SEED, ENTER_STAGE, READ and CLOSE_STAGE permissions, but **no RESOLVE_REVIEW permission and no review provider**. The independent probe uses real Ed25519 signatures and a real SQLite event store:

1. Open a case and commit a seed.
2. Change willingness under the same population snapshot/version; enter stage.
3. Observe `ACCUSATION_INPUT_DISCREPANCY_REVIEW`, reason `NON_IDEMPOTENT_SOURCE`.
4. Restore data, advance population and eligibility versions together.
5. Commit a fresh seed and enter the stage.
6. Actual result: `ACCUSATION_EMPANELED`, a real two-person roster, and event types `CASE_OPENED, SEED_COMMITTED, INPUT_DISCREPANCY, SEED_COMMITTED, STAGE_PLANNED`. There is no review event.

The [service seed-entry path](<https://github.com/ptown16801-lang/concord/blob/8a2e3773daba2b470d2fb027448789b6965f4075/src/governance/impeachment-service.js#L70>) checks whether a panel is frozen but not whether input-discrepancy review is pending. Its [review-resolution path](<https://github.com/ptown16801-lang/concord/blob/8a2e3773daba2b470d2fb027448789b6965f4075/src/governance/impeachment-service.js#L108>) accepts only POST_FREEZE_REVIEW. The common seed path affects both accusation and trial; R6 directly reproduced accusation.

The specification distinguishes ordinary WAITING retries after an attributable source change from defective-source review. A source version change supplies neither independent authorization nor an attributable resolution. This is a domain authorization/contract defect reachable by a configured clerk, not evidence of an unauthenticated remote exploit.

Required correction: persist the pending gate for both stages, require a trusted independently authorized resolution bound to the affected case/stage/discrepancy, journal the resolution, and require a fresh seed commitment before panel selection resumes. Preserve ordinary changed-source WAITING retries. Include source-capture errors and planner-reported discrepancies, restart persistence, invalid/mismatched review receipts and both stages in verification.
