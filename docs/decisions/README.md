# Decision register and historical evidence

Start with the maintained [documentation index](../README.md) for project purpose,
architecture and development instructions. [DECISIONS.md](../../DECISIONS.md)
is the published decision register; each entry retains its own acceptance and
implementation limits. [CURRENT_DECISIONS.md](../../CURRENT_DECISIONS.md) is
generated navigation, not a separate policy authority.

This directory preserves the September 2026 reconciliation and its source
snapshots. Dated receipts, review packets, branch comparisons and test counts
describe the revision named in each record. They are not current release status.
Use [development status](../PROJECT_STATUS.md) for the published baseline and
separate candidates.

The [source register](SOURCES.md) and `sources.json` retain stable source IDs.
Some snapshots are sanitized public derivatives; their registry entries distinguish
the public digest from the original digest and Git blob. A notice in place of a
private original preserves the reference without disclosing the original. A
notice is not evidence of a new acceptance or a substitute for missing technical
requirements. Internal machine/session inventories are preserved privately.

To maintain the register, follow the scoped instructions in the root
[contribution guide](../../CONTRIBUTING.md). Historical workflow records remain
evidence of their date; later explicit owner instructions govern current work.
